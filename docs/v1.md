## v1

### Resumen

Implementación inicial del blog **while(alive)** sobre **Next.js 16 (App Router)** + **React 19** + **Tailwind v4**. La PR introduce el esqueleto completo del sitio: layout, ruteo, tipado de contenidos, sistema de temas dual (Modo Cuaderno / Modo Terminal) y un primer flujo end-to-end para publicar cuentos y micro-posts (pensamientos, frases y preguntas) en memoria.

### Motivación

Establecer la base técnica y estética del proyecto descrita en el `README`: un refugio minimalista donde conviven una experiencia literaria (`Cuaderno`) y una experiencia técnica (`Terminal`), con la misma fuente de datos y el mismo flujo de publicación.

### Qué incluye

#### Configuración del proyecto

- `package.json` con dependencias principales: `next@16`, `react@19`, `next-themes`, `lucide-react`, `react-hook-form`, `zod`, `tailwindcss@4`, `@vercel/analytics`, `react-doctor`, etc.
- `tsconfig.json`, `next.config.mjs`, `postcss.config.mjs`, `tailwind.config.ts`, `components.json` (shadcn).
- Actualización de `.gitignore` para excluir entornos locales, `.next/`, `.vercel/`, y herramientas internas (`.agents/`, `.claude/`, `.cursor/`, `.kiro/`, `.react-doctor/`).
- Tipografías cargadas vía `next/font/google`: **Geist**, **Geist Mono** y **Lora**.

#### Sistema de temas dual

- `src/components/theme-provider.tsx`: contexto que maneja dos ejes independientes:
  - `theme`: `light` | `dark` (persistido en `localStorage` bajo la clave `theme`, con fallback a `prefers-color-scheme`).
  - `experience`: `notebook` | `terminal` (persistido en `localStorage` bajo la clave `experience`).
- Aplica `class="dark"` y `data-experience="…"` sobre `<html>` para conducir los estilos.
- Evita el flash de tema incorrecto en el primer render (`mounted`).

#### Layout y navegación

- `app/layout.tsx`: layout raíz con `ThemeProvider`, `Header`, metadatos SEO en español, iconos light/dark, `viewport` con color por preferencia y `@vercel/analytics` solo en producción.
- `src/components/layout/header.tsx`: logo dinámico (`while alive.` en serif vs `while(alive) { ▊ }` en monoespaciado), enlaces a `/nuevo`, toggle de tema y toggle de experiencia.

#### Páginas (App Router)

- `app/page.tsx` — Home con manifiesto adaptativo, feed de posts y footer dual.
- `app/nuevo/page.tsx` — Formulario para crear historias con consejos de escritura.
- `app/cuento/[slug]/page.tsx` — Lectura de cuento con `generateStaticParams`, `generateMetadata` (incluyendo OpenGraph) y `notFound()`.
- `app/cuento/[slug]/not-found.tsx` y `app/not-found.tsx` — Páginas 404.
- `app/globals.css` y `styles/globals.css` — Estilos base y tokens Tailwind.

#### Dominio: tipos y datos

- `src/types/story.ts`:
  - `PostType = "story" | "thought" | "phrase" | "question"`.
  - `Story` (cuento completo con `slug`, `excerpt`, `readingTime`) y `MicroPost` (máx. 280 caracteres).
  - Type guards `isStory` / `isMicroPost`.
  - `StoryFormData`, `MicroPostFormData`, `FilterType = "all" | "stories" | "logs"`.
- `src/data/stories.ts`: fuente de datos en memoria con helpers `getAllPosts`, `getAllStories`, `getStoryBySlug`, `addStory`, `addMicroPost`.

#### Server Actions

- `app/actions/story-actions.ts`:
  - `createStoryAction`: valida título (≤ 200), contenido (≤ 50 000), autor opcional (default `Anónimo`) y devuelve `{ success, slug }` o `{ error }`.
  - `createMicroPostAction`: valida `type`, contenido (≤ 280) y autor opcional.

#### Componentes de historias

- `src/components/stories/`:
  - `post-feed.tsx` — Feed con filtros y contadores adaptados a cada experiencia.
  - `story-card.tsx` / `micro-post-card.tsx` — Tarjetas por tipo de contenido.
  - `story-list.tsx` — Listado alternativo de cuentos.
  - `story-reader.tsx` — Vista de lectura del cuento.
  - `story-form.tsx` — Formulario con `react-hook-form` + `zod`.
  - `terminal-filter.tsx` — Filtros `ls --all` / `ls --stories` / `cat logs/` (o sus equivalentes literarios `Todo` / `Cuentos` / `Pensamientos`).
- Índices en `src/components/{layout,stories}/index.ts` y `src/types/index.ts`.

#### Utilidades y hooks

- `lib/utils.ts` (helper `cn` para clases).
- `hooks/use-mobile.ts`, `hooks/use-toast.ts`.
- `components/theme-provider.tsx` (wrapper compatible con la convención de shadcn).

### Cómo probar

```bash
pnpm install
pnpm dev
```

Luego visitar:

- `http://localhost:3000/` — Home con feed y toggles de tema/experiencia en el header.
- `http://localhost:3000/nuevo` — Crear un cuento (validaciones de título y contenido).
- `http://localhost:3000/cuento/<slug>` — Lectura de un cuento existente.
- Probar el cambio entre **Cuaderno** y **Terminal** y verificar que la preferencia persiste tras recargar.
- Probar el cambio entre claro/oscuro y verificar persistencia.
- Verificar 404 visitando un slug inexistente.


### Notas

- La fuente de datos vive en memoria (`src/data/stories.ts`); cualquier publicación se pierde al reiniciar el servidor. La integración con persistencia (p. ej. Supabase) se abordará en una PR posterior.
- `@vercel/analytics` solo se monta cuando `NODE_ENV === "production"`.
